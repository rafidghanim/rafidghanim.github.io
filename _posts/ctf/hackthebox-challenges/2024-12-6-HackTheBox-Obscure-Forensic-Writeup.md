## 🕵️ Forensics

### Challenge: Obscure [Easy]

**Description**

An attacker found a vulnerability in the web server that allowed arbitrary PHP file uploads to the Apache server. The attacker uploaded what looked like an obfuscated shell named `support.php`.

We were also given a short PCAP capture generated by `tcpdump`. The goal is to analyze the web shell and network traffic to identify the commands executed by the attacker and understand what data was compromised.

---

## Given Files

After extracting the attachment, we get three files:

```sh
user@parrot~> unzip Obscure.zip

inflating: 19-05-21_22532255.pcap
inflating: support.php
inflating to-do.txt
```

The `to-do.txt` file also explains the incident:

```txt
An attacker has found a vulnerability in our web server that allows arbitraty PHP file upload in our Apache server. Suchlike, the hacker has uploaded a what seems to be like an obfuscated shell (support.php). We monitor our network 24/7 and generate logs from tcpdump (we provided the log file for the period of two minutes before we terminated the HTTP service for investigation), however. we need your help in analyzing and identifying commands the attacker wrote to understand what was compromised.
```

From the description, we know that the suspicious activity is related to an uploaded PHP web shell. So, I started by analyzing `support.php`.

After formatting it, the logic becomes easier to understand:

```php

$k = "80e32263";
$kh = "6f8af44abea0";
$kf = "351039f4a7b5";
$p = "0UlYyJHG87EJqEz6";

function x($t, $k)
{
    $c = strlen($k);

    // print "$p$kh$r$kf";

```

From this code, we can identify several important values:

| Variable | Value |
|---|---|
| `$k` | `80e32263` |
| `$kh` | `6f8af44abea0` |
| `$kf` | `351039f4a7b5` |
| `$p` | `0UlYyJHG87EJqEz6` |

The backdoor reads data from `php://input`, then searches for this format:

```txt
$kh + base64_payload + $kf
```

The payload is then decoded, XOR-decrypted using the key `$k`, decompressed with `gzuncompress()`, and finally executed using `eval()`.

So, to recover the attacker’s commands, we need to look for HTTP POST requests that contain data between:

```txt
6f8af44abea0 ... 351039f4a7b5
```

## Payload 4: Exfiltrating the KeePass Database

```sh
user@parrot~> curl -X POST localhost:1337/shell.php -d "6f8af44abea0QKwu/Xr7GuFo56r7/X/jfHEdLv77HX4eaufRRXofHPkXukp5H/oZGfH8LuQCMrwmbybyl9RYnhQdJsKpqxrepRMoTSemlRLaXZdBZhoq75ohMhAxMvrQKEw351039f4a7b5"
#output
#chdir('/home/developer');@error_reporting(0);@system('base64 -w 0 pwdb.kdbx 2>&1');
```

The attacker executed:

```sh
chdir('/home/developer');
@error_reporting(0);
@system('base64 -w 0 pwdb.kdbx 2>&1');
```

This command reads `pwdb.kdbx`, encodes it with Base64, and returns it through the web shell. The file is likely a KeePass password database.

![Base64 encoded database output](/assets/img/hackthebox/obscure/07-decoding.png)

The decoded response contains the Base64 output of the `pwdb.kdbx` file.

To recover the database, I decoded the Base64 output and saved it as `pwdb.kdbx`:

```sh
user@parrot~> echo "<base64-output>" | base64 -d > pwdb.kdbx
```

After that, I cracked the KeePass database password using John the Ripper.

![John cracking result](/assets/img/hackthebox/obscure/08-result.png)

Finally, I opened the database using KeePass and found the flag.

![KeePass flag](/assets/img/hackthebox/obscure/09-flag.png)

## Conclusion

In this challenge, the attacker uploaded an obfuscated PHP web shell and used it to execute commands on the server. By deobfuscating the shell, we learned how the payload was encoded and encrypted. Then, by filtering the PCAP for HTTP POST requests, we recovered the attacker’s commands.

The attacker checked the web server user, listed `/home/`, moved into `/home/developer`, and exfiltrated a KeePass database named `pwdb.kdbx`. After decoding and cracking the database, we obtained the flag.
